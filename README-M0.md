# M0 可行性验证手册

> 目标：用半天时间回答一个决定项目生死的问题 ——
> **像素蛋糕能不能 1:1 无损地完成「合成 → 美颜 → 切回」？**
>
> 如果答案是"能"，后面全是纯工程；如果答案是"不能"，整个方案要重新设计。
> 所以**先花这半天，不要先写主程序**。

---

## 0. 一次性准备

像素蛋糕里请先建一个**空项目**，并把这些设置确认一遍：

| 位置 | 设置 | 为什么 |
|---|---|---|
| 导出 → 自定设置 → 图片格式 | **TIFF** | 唯一能无损往返的格式 |
| 导出 → 自定设置 → 品质 | **14**（最大） | 万一实际走了 JPG 编码，把损失压到最低 |
| 导出 → 自定设置 → 色彩空间 sRGB | **不勾** | 官方说明「不会改变色彩空间」，勾了反而可能被转一次 |
| 导出 → 排版印刷 | **关闭** | 官方明确说过它会改变画面范围、导致成品被裁 |
| 裁剪同步 | **不要用** | 同上，会把裁切规则带到别的图上 |

## 1. 第 1 轮：原样转存（最重要的一轮）

这一步**什么效果都不要加**。目的是把"传输管道"本身测干净。

```
1. 新建项目，导入  probes/probeR5.tif      ← 8192×10952，89.7MP
2. 不做任何编辑
3. 导出 → 自定设置 → TIFF → 品质 14 → 不勾 sRGB → 关闭排版印刷
4. 导出到  inbox/roundtrip/
5. 把导出的文件原样留在这个目录
```

然后运行：

```bash
cd /Users/wangjunfei/Desktop/harness/pixcake-tiler
node tools/m0-compare.mjs --name probeR5 --returned inbox/roundtrip/<导出后的文件名>
```

### ⚠️ 这一轮请顺手回答 4 个问题（直接决定架构）

1. **导出后的文件名和导入时一样吗？**
   你设想的"同名替换"能不能成立，全看这个。
   导出时请分别试一下**「指定文件夹」**和**「原始照片所在的文件夹」**两种，看看文件名有没有变化
   （比如被加了 `_1`、`_编辑`、时间戳）。

2. **导出会不会覆盖源文件？** 如果会，我们必须另存一份原始合成图。

3. **导出对话框里有没有「尺寸 / 分辨率 / 长边」之类的选项？** 有的话截图给我 —— 这是最大的风险点。
   官方文档列的「高级设置」只有：导出位置、图片格式、品质、色彩空间、水印，**没有尺寸项**，这是好兆头，但要以你亲眼看到的为准。

4. **打开 89.7MP 的图，软件流畅吗？有没有内存不足的提示？** 这决定我们一组拼几张、要不要设"保守/激进"档位。

## 2. 第 2 轮：只修上半张（测多人脸 + 跨界污染）

```
1. 重新导入 probes/probeR5.tif
2. 只对【上半张】做人像美化（右上角有白色方块的那一半）：
     磨皮、液化（瘦脸/大眼，故意拉大一点）、祛瑕疵
3. 下半张（黑色方块那一半）一个像素都不要碰
4. 导出 TIFF 到 inbox/edited/
```

```bash
node tools/m0-compare.mjs --name probeR5 --returned inbox/edited/<文件名> --edited-panel 0
```

这一轮会输出**接缝污染深度曲线**，直接告诉我们保护带要留多宽。如果都没事，保护带可以设很小。

同时请留意：像素蛋糕把这张图识别成**几个人**？能不能用「单人」逐个选中上下两半的人？
（探针上没有人脸，所以识别不到是正常的，但你可以顺便看看「人脸检测」界面长什么样。）

## 3. 第 3 轮：真实人像（测 AI 串味，最关键的效果验证）

```bash
# 1) 先把你调好色的两张 JPG 拷进 inbox/，然后：
node tools/m0-generate.mjs portrait --inputs inbox/你的A.jpg,inbox/你的B.jpg --name probeReal

# 2. 把它丢进像素蛋糕，用你平时真用的那套功能走一遍，导出 TIFF
# 3. 比对：
node tools/m0-compare.mjs --name probeReal --returned inbox/<文件名> --edited-panel 0
```

**这一轮要看的是「效果」而不是「像素」**，请你直接用眼睛判断：

- 两半的肤色/亮度有没有被「拉向同一个平均值」？（这是全图自适应统计串味，最危险）
- 「所有人」档的磨皮强度，对两半是不是都合适？
- 「背景祛瑕疵 / 背景祛穿帮 / AI祛路人」这类全图 AI，会不会把 A 半的内容补到 B 半？
- 液化的时候，另一半有没有被拽动？

**建议拿两张同一次拍摄、同一光线的照片**来测。跨场景混拼的效果我不保证，这也是我要在文档里写明的使用边界。

## 附：工具自带的自检

比对器本身是可信的 —— 我用三个"故意做坏"的样本验证过它的灵敏度：

| 人为故障 | 检测结果 |
|---|---|
| 整图缩到 75% 再拉回（模拟内部低分辨率处理） | ✔ 抓到：2px 光栅对比度只剩 **7.8%**，孤立亮点只剩 25.1%，1px 边框被糊，PSNR 18.0 dB |
| 等比缩到 75% 不拉回（模拟导出改尺寸） | ✔ 抓到：尺寸 1500×2268，比值 0.750000，判定为"最坏情况" |
| 轻微 gamma 拉伸 + 饱和 +8%（模拟色彩空间被转） | ✔ 抓到：最大色差 **ΔE76 = 4.18**，灰阶偏差 11.0 |
| 同一文件当返回文件（对照组） | ✔ 全绿，PSNR ∞ |
