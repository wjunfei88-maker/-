# 像素拼图 · PixCake Tiler

把多张照片 **1:1 无损**拼成一张像素蛋糕能处理的画布，美颜后按记录切回原图。
四张合一 → 像素蛋糕只扣一张额度 → 切回四张。

> 面向 42–45MP 机型的实测结论：**一组 2 张，省 50%**。
> 这不是实现限制，是几何决定的 —— 见下面「为什么是 2 张」。

## 使用流程

**① 导入** — 把调好色的 JPG 拖进窗口，或按 `⌘O`

**② 自动排版** — 按 12000px 上限算出最优摆法。装不下会自动拆成多张画布，
顶部用 `‹ 1/2 · 2张 ›` 切换。每一张画布对应像素蛋糕的一次额度。

也可以手动拖：拖到接近另一张时自动吸附，**永远不允许重叠**
（重叠意味着被压住的像素在画布里根本不存在，切分时无处可取）。

**③ 导出合成图** — 得到三个文件，放在一起：

```
TILE_batch_a3f9c1.tif            无损合成图（LZW TIFF）
TILE_batch_a3f9c1.manifest.json  每张原图的位置尺寸记录（切分的唯一依据）
TILE_batch_a3f9c1.preview.jpg    预览图
```

**④ 过像素蛋糕**

- 导入 TIFF → 正常美颜 → **导出时选 TIFF，品质 14**
- **不要改文件名**，导出到同一目录（实测像素蛋糕本来就保持原名）
- 不要开「排版印刷」，不要把「裁剪」同步进去 —— 这两件事会改变画面范围
- **别重新生成合成图**：官方规则是「修改或替换原始文件会重新计费」，
  同一个合成图反复修反复导只扣一次

**⑤ 切回原图** — 点顶部「切回原图」，选像素蛋糕导出的那个文件。
软件自动在同目录找到 manifest，按记录的绝对矩形做整数像素裁剪，
并把原图的 EXIF 搬回来（同时摘掉内嵌的旧缩略图，否则客户在访达里会看到没修过的版本）。

## 为什么是 2 张（很重要）

像素蛋糕的导入上限是**单边 12000px**，不是总面积。所以「能拼几张」是纯几何问题：

| 单张尺寸 | 一列能放 | 一行能放 | 上限 | 省额度 |
|---|---|---|---|---|
| 7952×5304（42MP, A7R3/R4） | 2 | 1 | **2 张** | **50%** |
| 8192×5464（45MP, R5） | 2 | 1 | **2 张** | **50%** |
| 6000×4000（24MP） | 3 | 2 | 6 张 | 83% |
| 9504×6336（61MP, A7R5） | 1 | 1 | 1 张 | 0% |

42MP 横图：`⌊12000/7952⌋ = 1`、`⌊12000/5304⌋ = 2` → 只能上下叠两张。
左右排是 15904px，超限。想塞第 3 张得缩到 0.75 倍（掉 43% 像素），
违背「像素量不减少」，所以默认不做。

**尺寸混杂时**走货架打包，利用率更高。

## 关键设计决策（都有实测依据）

这些不是拍脑袋，来自 `M0-结果.md` 里的两轮实测。

### 1. 保护带里填「各自的边缘镜像」，不是灰底、不是隔壁图

实测发现液化的形变是一个**全局平滑位移场**：只在上半张液化，位移会跨过接缝
继续衰减到下半张（峰值 5px → 跨过接缝后不足 1px，到 520px 深处精确归零）。

所以保护带的作用不是「挡住」形变，而是**让每一侧被拉扯时取到的是自己的内容**。
如果填隔壁图或纯黑，边缘就会被污染。24px 足够。

### 2. 合成图必须是 3 通道 RGB

libvips 的 `composite` 会把底图提升成 4 带（RGBA）。不压回去就会多出 25% 体积，
而且下游按 3 通道读数会错位。已在 `removeAlpha()` 里处理，并写进了自动断言。

### 3. EXIF 走「整体搬运 APP1 段字节」，不用 sharp 的 withExif

sharp 的 `withExif` 只接受字符串值（ISO/光圈/快门这类数值标签会被破坏），
而且官方明确写了不支持 TIFF 输出。所以直接搬运原图的 EXIF 段字节，
MakerNotes / GPS / 镜头数据全保真。另外把 IFD0 指向缩略图的 next-IFD 指针清零，
彻底断开内嵌的旧缩略图。

### 4. 切割前必须校验尺寸，绝不猜着切

如果返回文件尺寸和合成时不一致：
- 等比缩放 → 按比例映射裁剪框继续切（会有一次重采样，明确告知）
- 宽高比也变了 → **直接拒绝并报错**

    main.mjs                 窗口、IPC、pcfile:// 协议

      library.mjs            导入、方向归一、缩略图

      split.mjs             切分 + 尺寸校验
      exif.mjs              EXIF 搬运 + 缩略图摘除
  renderer/                  React 界面
    src/App.jsx              状态编排、批次队列、快捷键
    src/lib/geom.js          贴边吸附 / 强制留缝 / 禁止重叠
    src/lib/pcfile.js        本地图片 URL（有个 URL 小写化的坑，见注释）
    src/components/          Stage / Filmstrip / Inspector / Chrome
  test/e2e.mjs               后端全链路回归测试
  test/e2e.mjs               后端全链路回归测试
tools/                       M0 探针工具（验证像素蛋糕行为的仪器）
scripts/
  dev.mjs                    开发启动器（Vite 就绪后拉起 Electron）
  make-icon.mjs              用 SVG 生成 .icns 图标
  package.mjs                打包成 .app（可选 --dmg）

build/icon.icns              应用图标
```

**性能**：合成 89.7MP 画布实测 **3–4 秒**，LZW 后 56–61MB（未压缩 242MB，压 4.3×）。
走 libvips 流式管线，峰值内存远低于在 JS 里开一张 242MB 的 Buffer。

## 已知限制

- **只对精修页按张计费的功能有效**。创意模块的 AI 工具是按「点/人/次」算的，合并反而更贵。
- **不适合跨场景混拼**。像素蛋糕的「肤色统一」「AI色彩」等会统计整张画布 ——
  虽然你的工作流（先统一调色）已经消掉大部分风险，但不同场景硬拼仍可能让两边都偏。
  最安全的组合是同一次拍摄、同一光线的一组照片。
- **液化离接缝太近会轻微波及另一半**（亚像素级，肉眼不可辨）。峰值间距建议 >1500px。
- 手动拖动目前限制在自动排版给出的画布范围内；要改布局请重新「自动排版」。
- 打包产物**没有做代码签名和公证**。本机运行没问题；拷给别人时对方需要「右键 → 打开」放行一次。
- 只打了 arm64（M 系列）。要在 Intel Mac 上跑需要 `--arch=x64` 重打，或做通用二进制。
